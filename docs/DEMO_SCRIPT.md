# 3-minute Demo Script

## 0:00–0:25｜问题

“测试工程师手里不是没有数据，而是数据到结论之间还隔着清洗、找稳态、看阈值和写报告。H₂ TestLens 把这条链压缩成一次导入。”

## 0:25–1:05｜载入样本

点击“载入演示样本”。先看结论为“未通过”，再指出页面没有只给一个红色结果：它同时展示了数据完整率、稳态电压波动、温度、压力和泄漏监测。

## 1:05–1:45｜解释异常

进入“风险清单”，展示压力和泄漏异常。强调每项都绑定三件事：实际证据、触发阈值、建议动作。工程师知道先复核哪里，不需要重新翻原始日志。

## 1:45–2:15｜证明可配置

把压力上限从 30 调到 32，把泄漏上限从 10 调到 15，点击“应用阈值并重新分析”。结论从“未通过”变为“需复核”，说明规则来自可配置标准，不是写死的魔法数字。

## 2:00–2:20｜批次对比

点击“载入演示基线并对比”。展示基线 `PASS` 到当前 `FAIL` 的判定变化，再指出压力、泄漏和压力漂移的 KPI 差值，以及“新增风险”清单。强调系统展示证据差值，不把单个指标的升降直接解释成好坏。

顺手切换“燃料电池 · 演示模板”，指出阈值、报告来源和风险判定会一起变化；手工改值后会进入“自定义阈值 · 当前会话”。

点击“保存当前批次”，换载中文单位样本再保存，展示本地历史只保留摘要，并自动与上一批对比；刷新页面后 `2 条摘要` 仍在。

## 2:20–2:40｜AI 报告助手

点击“生成证据约束草稿”。先展示本地证据模式：它用结构化 KPI、风险和阈值生成草稿，不上传原始行；现场若配置企业模型网关，则同一证据包可以切换到 OpenAI-compatible 模型。

## 2:40–2:55｜报告与证据

点击“下载 Markdown 报告”和“JSON”。报告适合工程师继续编辑，JSON 适合接入工单或质量系统。指出报告底部的边界：演示阈值不等于企业安全标准，最终需要人工签核。

## 2:55–3:00｜现场升级点

“拿到企业资料包后，我们会先做字段映射和设备模板，再把大模型放在报告初稿层；大模型只能引用规则引擎已经算出的证据，不能越权改变判定。”
