# Requirement Spec

## Problem

氢能设备测试工程师面对多源测试日志时，常见工作链是“清洗数据—找稳态段—看阈值—截图—写报告”。人工整理慢，异常证据与建议动作容易脱节，也难以让不同工程师复用同一套判定口径。

## Chosen track

选择 T02「设备测试数据分析与自动报告」。原因：

1. 业务价值清楚：缩短测试后处理时间，提升异常分流一致性。
2. 线上可用脱敏 CSV 做端到端演示，不依赖企业内网账号。
3. 适合在 24 小时现场继续接入企业字段和标准，风险低于直接做设备控制。

## Product promise

给定一份设备测试 CSV，5 秒内完成首轮分析，输出：

- 工况分段和数据完整率；
- 关键 KPI 与趋势图；
- 带证据的风险清单；
- 可编辑阈值下的自动判定；
- 中文报告草稿和 JSON 证据包。
- 一键生成证据约束的 AI 报告草稿；无模型配置时必须可本地回退。
- 可将当前批次与基线批次对比，展示 KPI 差值、判定变化和风险新增/消除。
- 可按设备 profile 加载一组阈值，并支持当前会话自定义；profile 名称和来源必须进入报告。
- 可将批次摘要保存到本地历史，刷新后仍可查看；原始测试行不得写入历史摘要。
- 可导入带 schemaVersion 的企业 profile/fieldMapping JSON 包，并在当前分析中显示组织与配置来源。

## Acceptance criteria

- 用户无需登录即可载入演示样本或导入 CSV。
- 每个结论都能回指计算指标、当前阈值和建议动作。
- 同一份 CSV 更改阈值后可以重新分析，结果会变化。
- 报告可以下载，且明确“演示阈值”和“需要工程师签核”。
- AI 草稿只能引用结构化分析证据，不能改变自动判定或读取原始行。
- 批次对比不能把单个 KPI 的升降直接包装成“变好/变坏”，必须同时显示差值和风险证据。
- 内置 profile 必须标注为演示模板，不能冒充企业安全标准。
- 本地历史功能必须明确数据范围，并提供清除入口。
- 远程 AI 返回空内容、冲突判定或无证据锚点时，必须自动回退本地草稿。
- 标准引用、方法版本、审批状态或测试元数据缺失时，系统必须显示 `DEMO_ONLY/NOT_READY`，不能输出标准符合性结论。
- 不把规则原型包装成安全认证或最终工程决策。
