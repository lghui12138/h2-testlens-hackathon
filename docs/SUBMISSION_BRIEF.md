# 浦发·IGNITE 未来能源黑客松参赛 Brief

## 赛道选择

选择赛道一 T02「设备测试数据分析与自动报告」。

## 一句话作品

H₂ TestLens 把一份氢能设备测试日志变成工程师可复核、可行动、可追溯的报告：自动完成字段适配、单位换算、稳态窗口分析、风险分流、批次对比和证据约束 AI 草稿。

## 真实问题

测试工程师常见流程是：清洗多种导出格式 → 找稳态段 → 对照阈值 → 截图 → 手写报告。问题不在于没有数据，而在于数据、结论和下一步动作之间缺少统一链路。

## 现场 3 分钟演示

1. 载入标准样本：展示 `25` 条记录、`FAIL` 判定、压力/泄漏风险和建议动作。
2. 载入中文单位样本：展示 `8/8` 字段映射和 `5` 项单位换算。
3. 切换设备 profile 或修改阈值：展示规则可配置且来源可追溯。
4. 点击“载入示例企业配置”：展示组织、企业 profile 和 `字段映射 8/8`；真实 JSON 包可替换它。
5. 载入基线并对比：展示 `PASS → FAIL`、KPI 差值和新增风险。
6. 保存两批摘要并刷新：展示本地历史只保存摘要，不保存原始行。
7. 生成 AI 草稿：展示批次证据、判定和优先动作；远程模型输出不符合 grounding guard 时自动回退。

## 为什么是 AI × 氢能

AI 不直接控制设备，也不替工程师签安全结论。规则引擎先产生结构化证据，AI 只负责把证据组织成报告初稿；判定、阈值、原始数据边界和人工签核始终保留。

## 可验证证据

- `npm test`：覆盖解析、数据质量、单位、profile、批次对比、历史和 AI guard。
- `npm run eval:ai`：4 类 grounding fixture，只有正确 verdict + 证据锚点的模型输出允许通过。
- `npm run check:submission`：检查参赛文件、T02 口径、测试和 AI 评估是否齐全。
- `npm run smoke:api`：验证工单/质量系统可通过 loopback API 获取结构化结果，且原始行不出接口。
- Chrome 页面：标准样本、中文单位样本、profile、历史保存和批次对比均可交互。

## 24 小时现场扩展计划

第一阶段接入企业数据字典和一份脱敏测试文件，确认字段、单位和设备 profile；第二阶段替换通用演示阈值，补充真实历史批次和异常案例；第三阶段在企业批准的模型网关上跑 grounding/延迟/可用性评估；最后输出企业格式报告和工单系统接口。

## 诚实边界

当前样本、profile 和阈值是演示用，不代表企业安全标准；远程模型尚未在企业网关和真实数据上评估。正式提交时替换数据与标准，但保留本地规则 fallback 和人工签核。
