# Independent deployment boundary

## Current public surface

- Repository: `https://github.com/lghui12138/h2-testlens-hackathon`
- Pages URL: `https://lghui.top/h2-testlens-hackathon/`
- Workflow: `.github/workflows/deploy-pages.yml`
- Build artifact: `_site/` generated by `scripts/prepare-github-pages.mjs`

The Pages build is intentionally static. It runs the audited browser analyzer, loads sample/config assets by relative paths, keeps raw CSV rows in the browser, and falls back to the local evidence draft when `/api/ai-draft` is unavailable.

## Authentication boundary

The public Pages surface currently has no account system. Local history is browser-local only; it is not a user account or shared database. Do not add a fake `localStorage` registration flow.

Normal registration requires an approved external identity provider such as email/password or GitHub OAuth, plus server-side/session and data-access rules. Provider secrets must never be committed to this public repository or exposed as frontend secrets. When an auth provider is selected, add the provider callback/allowed-origin settings and test sign-up, email confirmation, sign-in, sign-out, password reset, and unauthorized data access before calling the registration flow production-ready.

## Release gate

Every push to `main` runs `npm run check:submission`, builds `_site/`, uploads a GitHub Pages artifact, and deploys it. A green Actions run proves build/deployment integrity; it does not prove enterprise standards approval or user-authentication readiness.
