## 逐文件覆盖审计（2026-08-23，v3.5.36）

v3.5.35 实际重放结果：198/198 文件、190 processed、6 reference_only、1 blocked_binary、1 declared_no_upload，2,262,283 行/功率点进入适配器，198/198 使用台账，7/7 参考边界文件交叉链接，0 个重复 processed SHA-256，0 个正式符合性声明；170 个车辆文件按 T02 描述性 profile 执行动态设定变化分析，共 15,281 个事件，其中 3,727 个进入响应带并满足保持窗口，11,554 个未稳定/数据不足，0 个超过配置上限的采样缺口；真实 XLSX 有 6,572 个公式单元格且 6,572 个有缓存值，正式验收仍需人工公式复核；源完整性核对 198/198 文件大小和 SHA-256 一致，参考审计 7 个文件、0 个解析错误、21/21 条关键词证据完整。动态事件统计按文件/会话隔离，不是 GB/T 46104-2025 的动态试验合格判定。上述机器证据不等于标准全文人工复核或标准符合性。

输入安全续项：原始时序/参数 XLSX 在进入 vendored SheetJS 前统一执行 ZIP 预检：64 MiB 压缩输入、256 MiB 声明展开大小、2048 条目和 200:1 压缩比，并阻断损坏目录、ZIP64、加密条目和不支持的压缩方法。当前 T02 最大 XLSX 约 2.6 MiB，因此这些值是资源保护余量，不是标准限值。正式生产仍需隔离解析器及宏/公式、原型污染、ReDoS 和恶意工作簿安全验证。

T02 示例 profile 包：`config/t02-profile.example.json` 与 `public/config/t02-profile.example.json`。三个 profile 分别对应 vehicle、stack、durability；均为未审批 `descriptive_only`，限制单一数据类型，`thresholds: null`。若企业要进入 `risk_screening` 或 `acceptance`，必须另行提供批准 profile、目标限值、验收规则、仪器/不确定度证据和人工签核链，不能把示例 profile 直接升级。

## 页面侧已实现

- 真实 XLSX 工作簿的结构化证据不再只停留在“选中稳定性工作表”：8/8 工作表均保留角色和状态；静态矩阵仅输出描述性统计，出厂报告的“是否合格”只复述原报告字段，BD 身份和未命名产品列不进入公开 JSON 或系统标准判定。

- 上传入口支持 CSV、UTF-8/GB18030 或带明确 BOM 的 UTF-16 TXT、制表符 TSV 和原始时序 XLSX；仅在解码后文本控制字符比例正常时放行，Excel 会从最匹配时间/电流/电压字段的工作表读取，不把参数工作簿当成原始数据。
- 车辆数据自动识别 `FC_*` 信号；目标电流、允许波动和最短持续时间在页面中可调整。
- 电堆数据自动识别中文字段和 `CELL1…`/`单片电压1…` 通道；同一分析同时保留原始字段名到标准字段的映射，并输出 127 列覆盖层、设定/实测偏差核对和阀/泵反馈摘要。
- 车辆分析保留 46 列信号目录，支持选择任一有数值记录的展示信号和相对时间窗口；核心运行信号、上下限/总电压交叉核对与仅目录字段分层展示。
- 真实企业结构的异常只输出证据和下一步动作：时间分辨率不足、字段缺失、单片数量与通道数不一致、绝缘无效码等不会被静默修正。
- 页面专用图与表使用同一结构化结果：车辆图绘制绝缘趋势和 350/250 kΩ 线，电堆图绘制有效极化点并区分 60–120 s 短稳定点。
- 耐久 DOCX 解析保留原始报告元数据和功率点来源；未配置企业预警阈值时只显示原始结果，不新增判定。
- 飞书告警默认不外发；只有填写企业批准的 V2 webhook 并点击确认发送才会尝试 POST，发送结果保留在当前页面，不保存 webhook/密钥。
- 多文件批次会生成本地 manifest，按文件 SHA-256、大小、记录数和时间范围标记新增/变更/未变；manifest 不上传外部。
- 多文件车辆/电堆分析保留 `session_id` 和来源文件；目标电流段、绝缘窗口、电流平台和稳定区间不会跨文件拼接。车辆主图的左轴/右轴信号可独立选择、独立缩放，并在处理日志中留证。
- v3.5.14 新增声明式跨文件批次汇总：只有企业提供 `h2-testlens.batch-declaration.v1`，并明确 `testRunId`、`sessionGroup`、文件顺序、时钟引用、采样频率和重启边界后，watcher/API 才会生成 `declared_grouped_sessions` 描述性汇总；每个文件仍是独立 `session_id`，不把不同文件自动拼成连续时序。
